<objective>
Build the TikTok-style feed surface itself: full-screen, one trip at a time, vertical swipe between trips and horizontal swipe between that trip's stops (D-01), with the fixed header/footer chrome of D-02 and the no-photo text fallback of D-03.

This is the largest genuinely-new frontend piece in the phase. Nothing in this codebase is a swipeable primitive — `stop-photo-gallery` is a static grid — and Ionic no longer ships `ion-slides`, so Swiper.js enters as a new dependency behind a legitimacy checkpoint. The plan leads with a tracer that gets one real trip rendering full-screen through the outer vertical swiper before any card chrome or fallback logic is written, so a nested-Swiper dead end surfaces after one commit rather than after the whole feed is built on it.

The action rail (D-04) is deliberately not here — plan 06-03 adds it into the card this plan creates.

Purpose: SOCIAL-01's user-facing half.
Output: A `/feed` route rendering a working nested-swipe feed from live backend data.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → `frontend/node_modules` | A new third-party package and its transitive tree enter the build |
| Backend feed response → Angular template | Server-supplied trip title, description, stop notes and photo URLs are rendered into the DOM |
| Browser route → `/feed` | An unauthenticated visitor may attempt to reach the feed surface directly |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-02-SC | Tampering | `npm install swiper` | high | mitigate | Task 1 is a blocking human legitimacy checkpoint (SUS verdict from the research audit) verifying the npmjs page, repo org, download volume and deprecation status; Task 2 pins the exact confirmed version with no caret so a later release cannot silently enter the build. |
| T-06-02-01 | Tampering (stored XSS) | Rendering `trip.description`, `stop.notes`, `trip.title` in the card | medium | mitigate | All user-supplied text is rendered through Angular interpolation, which escapes by default. No `innerHTML`, `bypassSecurityTrustHtml` or `DomSanitizer` bypass is introduced anywhere in this plan. |
| T-06-02-02 | Tampering | `stop.photoUrls[0]` bound to an `img` `src` | low | accept | URLs originate from the app's own Cloudinary-backed `StopPhoto.url` column, written only through the existing signed-upload path; Angular's `img src` binding does not execute script. Accepted rather than adding a URL allowlist for a value the app itself produced. |
| T-06-02-03 | Elevation of Privilege | `/feed` route reachable without a session | medium | mitigate | `canActivate: [authGuard]` on the route (defense in depth) plus the server-side authentication requirement landed in 06-01 — the guard is UX, the 401 is the actual control. |
| T-06-02-04 | Denial of Service | Unbounded feed paging accumulating DOM nodes | low | accept | Page size is server-bounded at 20 and appending is user-driven one swipe at a time; virtualization is not warranted at capstone data volume. Revisit if a feed session routinely exceeds several hundred loaded trips. |
</threat_model>
