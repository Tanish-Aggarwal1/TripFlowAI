<interface_context>
`ApiError` (backend/src/main/java/com/tripflow/backend/exception/ApiError.java) is a
plain class with a five-argument constructor:

    ApiError(int status, String error, String message, String path, List<FieldError> fieldErrors)

`fieldErrors` is `@Getter`-exposed and has no `@JsonInclude` annotation, so a `null`
value serializes as `"fieldErrors": null` — present, but null. `GlobalExceptionHandler`
passes `null` on every non-validation path (see its private `error(...)` helper and
every handler except `handleValidation`). `SecurityErrorWriter.write(...)` is the only
caller in the codebase that passes an empty list instead.

`SecurityErrorWriter` is package-private (`final class`, private constructor) and is
called only by `JsonAuthenticationEntryPoint.commence` and
`JsonAccessDeniedHandler.handle`, both in `com.tripflow.backend.security`.

`TripControllerIT` test-support helpers already available in the file: `createTestUser(String)`,
`createTrip(User, CreateTripRequest)`, `sampleTripRequest(String, TripVisibility)`, and the
`asUser(User)` `RequestPostProcessor`. `jsonPath` and `status` are already statically imported.
</interface_context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client -> Spring Security filter chain | Requests with no/expired/malformed bearer token reach `JsonAuthenticationEntryPoint` before the DispatcherServlet |
| authenticated client -> application authorization | A valid token belonging to a non-owner reaches `TripOwnershipService`, which raises `ForbiddenException` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `SecurityErrorWriter.write` error body | low | mitigate | Body remains status/error/message/path/timestamp only; the fieldErrors change removes content, never adds. No exception message, stack frame, or constraint name is introduced. |
| T-01-02 | Spoofing | `TripController` current-user resolution | medium | mitigate | Task 2 Edit C adds a reflection gate that fails the build if a controller method reverts to `Authentication`/`Principal` name-string resolution, which is the class of change that historically enabled principal-confusion bugs. |
| T-01-03 | Repudiation | 403 vs 404 disclosure on non-owned trips | low | accept | Existing behavior (403 for delete-by-non-owner, 404 for private-trip-as-non-owner) is deliberate and documented in `docs/auth.md`; standardizing existence-hiding is tracked separately as SCRUM-274 under Phase 6, out of scope here. |
</threat_model>
