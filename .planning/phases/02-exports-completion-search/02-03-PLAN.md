<objective>
Ship EXPORT-03: trip responses carry visited/total stop counts and a completion percentage, computed once, safe on zero-stop trips, and exposed to the trip's owner without leaking a stranger's progress into the public discovery feed.

Purpose: "3 of 7 stops done" is the number that makes a trip list feel like a live itinerary instead of a filing cabinet. The whole risk here is not the arithmetic — it is D-08's DTO fork: `TripSummaryResponse` is shared by the owner list, the discovery listing, and the discovery search, so the obvious one-record change would publish every user's progress to strangers.

Output: a new `TripOwnerSummaryResponse`, completion fields on `TripResponse`, and a completion badge on the dashboard trip card.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `GET /api/trips` | An authenticated `UserPrincipal` crosses here; the response must contain only this user's trips and only this user's progress. |
| owner-list query <-> discovery-feed query | Two response shapes served from the same table by different queries; the boundary between them is what keeps one user's progress out of another user's feed. |
| browser -> `GET /api/discovery/trips` / `GET /api/discovery/search` | Untrusted requester reads other users' PUBLIC trips. Not modified by this plan — and that is the point. |
